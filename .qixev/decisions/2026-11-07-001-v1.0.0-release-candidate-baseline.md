# ADR-001: Baseline Release Candidate Configuration for Qixev FieldKit v1.0.0

## Metadata
- Date: 2026-11-07
- Status: Proposed (Pending Human Approval)
- Author: Antigravity Agent
- Approved By: Pending Human Operator Review

---

## Context & Problem Statement
[FACT] Qixev FieldKit has reached feature readiness for its first public release candidate following the completion of Experiment #001 (User Validation) and Experiment #002 (Generic Work Units and Discrete Inventory Usage).
[FACT] The application has zero network permissions, is 100% offline, operates with a single SQLite Room database, and has 39 passing on-device connected instrumentation tests on the primary target hardware (Redmi 7 / Android 16).
[INFERENCE] A formal release candidate baseline decision record is required to establish versioning, signing constraints, packaging formats, and distribution readiness boundaries before code-freeze and tagging.

---

## Considered Options

1. **Option A: Pure APK Distribution (GitHub / Direct APK Download)**
   - *Pros*: Direct, simple, immediate distribution to field technicians without store review gates.
   - *Cons*: Does not prepare the project for Play Store compliance or app bundle optimization.

2. **Option B: Dual Artifact Packaging (Signed APK + Signed Android App Bundle)**
   - *Pros*: Provides signed APK for direct distribution and test installation; produces signed AAB (`app-release.aab`) ready for Google Play Store upload without additional build steps.
   - *Cons*: Requires managing both APK and AAB build configurations.

---

## Decision Outcome
[PROPOSAL] Adopt **Option B (Dual Artifact Packaging)**.
- Release APK path: `app/build/outputs/apk/release/app-release.apk` (1.56 MB)
- Release AAB path: `app/build/outputs/bundle/release/app-release.aab` (3.78 MB)
- Version metadata: `versionCode = 100`, `versionName = "1.0.0"`, `applicationId = "com.qixev.qfieldkit"`.
- Release signing: Dedicated key configured via untracked `keystore.properties` (fallback to debug key strictly rejected by Gradle build logic).

---

## Positive Consequences
- [FACT] `assembleRelease` produces a shrunk (1.56 MB) APK with R8 code and resource minification.
- [FACT] `bundleRelease` compiles and packages a signed release bundle (3.78 MB) in 7s without configuration drift.
- [FACT] Full cryptographic signature verified on release artifacts (v2 scheme on APK via `apksigner`; signed JAR structure on AAB via `jarsigner`).

---

## Negative Consequences & Trade-offs
- [FACT] AAB cannot be directly sideloaded via standard `adb install` without extraction via `bundletool`.
- [INFERENCE] Release builds require local availability of `keystore.properties` containing valid keystore credentials.
