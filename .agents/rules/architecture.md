# Architecture Rules & System Boundaries

This document defines the architectural rules, layer boundaries, and component responsibilities for **Qixev FieldKit**.

---

## 2. Layer Constraints & Invariants

### 1. UI Layer (`com.qixev.qfieldkit.ui.*`)
- **No Direct Storage Access**: UI composables must never access DAOs, Room database instances, or file streams directly.
- **Stateless & Declarative**: Screens must consume a single immutable `UiState` and emit user intents via lambdas.
- **No Side Effects**: Composable functions must remain free of asynchronous side-effects except via controlled `LaunchedEffect` or `rememberCoroutineScope`.

### 2. ViewModel Layer (`com.qixev.qfieldkit.ui.*ViewModel`)
- **StateFlow Emission**: ViewModels must expose state via `StateFlow` created using `stateIn(scope = viewModelScope, started = SharingStarted.WhileSubscribed(5_000L), initialValue = ...)`.
- **Pure Intents**: ViewModel functions representing UI events must be synchronous calls that launch coroutines internally if needed.
- **Zero Framework Coupling**: ViewModels must not reference Android `Context`, Compose nodes, or View hierarchies.
- **Factory Pattern**: ViewModels are instantiated via explicit `ViewModelProvider.Factory` implementations. Do not add dependency injection frameworks like Hilt or Koin.

### 3. Repository Layer (`com.qixev.qfieldkit.data.repository.*`, `com.qixev.qfieldkit.data.backup.*`)
- **Single Source of Truth**: Repositories abstract the database and provide Kotlin coroutine-first APIs (either `Flow<T>` or `suspend fun`).
- **Atomic Operations**: All mutations that affect multiple entities (e.g. creating a repair job, consuming parts from inventory, returning stock on job cancellation) must be wrapped inside a Room transaction using `database.withTransaction {}` or `database.runInTransaction {}`.
- **Negative Stock Prevention**: Inventory quantities must be validated before deducting stock. Repositories must return typed `OperationResult` or `RepairJobResult` rather than throwing silent exceptions.

### 4. Persistence & Database Layer (`com.qixev.qfieldkit.data.local.*`)
- **Entity Immutability**: All Room entities (`InventoryItemEntity`, `RepairJobEntity`, `JobPartCrossRef`) must be immutable data classes (`val` properties only).
- **Foreign Key Enforcement**: Child entities must declare foreign keys with matching indices and explicit `onDelete` actions (e.g., `JobPartCrossRef` cascades on job deletion, restricts on inventory deletion).
- **Type Converters**: Complex types (e.g., `JobStatus`) must use deterministic converters defined in `FieldKitConverters`.
- **Migrations**: Database version bumps must include an explicit `Migration` object in `Migrations.kt` and an accompanying automated migration test in `DatabaseMigrationTest.kt`.

### 5. Application Preferences (`com.qixev.qfieldkit.data.preferences.*`)
- App-level UI state (e.g., first-run onboarding status) must reside in `SharedPreferences` via `OnboardingPreferences`.
- Never store UI preferences or temporary flags inside Room business tables.
